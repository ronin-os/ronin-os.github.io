RōninOS Vom Kernel zur sicheren OS-Plattform – mit GUI, Netzwerk und Userspace

RōninOS ist ein freestanding x86-Kernel mit präemptivem Scheduling, vollwertigem TCP/IP-Stack (lwIP), GUI-Compositor mit Fenstersystem, dynamischem ELF-Linker, IPC (Shared Memory, Semaphoren, Sockets), Unix-ähnlichem Signal-Handling, PCI-Treiber-Modell, AHCI SATA und 20+ Userspace-Programmen – vollständig in C, kompilierbar via Docker-Cross-Toolchain.

Unsere Vision 🎯

Ein Betriebssystem, das Sicherheit und Souveränität nicht als Option, sondern als architektonisches Fundament betrachtet.

🔓

100 % Open Source

Der vollständige Quellcode ist öffentlich einsehbar und auditierbar. Keine proprietären Binary-Blobs, keine versteckten Telemetrie-Komponenten – vollständige Transparenz von der Bootsequenz bis zur Anwendungsebene.

🔒

Security by Design

Sicherheit wird nicht als nachträgliches Feature implementiert, sondern ist integraler Bestandteil der Systemarchitektur. Speicherisolierung, gehärtete Userspace-Prozesse und minimales Privilegien-Modell bilden das Fundament.

🔑

Verschlüsselung als Standard

Full-Disk-Encryption auf Block-Ebene, signierte Update-Ketten und Ende-zu-Ende-verschlüsselte Kommunikation. Der Benutzer behält die alleinige Kontrolle über seine Daten – der OS-Hersteller hat standardmäßig keinen Zugriff.

🌍

Unabhängig & Souverän

Keine Abhängigkeit von Konzernen, keine Telemetrie-Infrastruktur, kein Vendor-Lock-in. RōninOS läuft vollständig autark auf der Hardware des Benutzers – ohne externe Zugriffe oder verpflichtende Cloud-Dienste.

Kernkomponenten 🧱

15 modulare Subsysteme, die das technische Fundament des Kernels bilden – von der Speicherverwaltung bis zum GUI-Compositor.

01

Physical Memory Manager

Bitmap-basierte 4-KiB-Frame-Verwaltung auf Basis der Multiboot2-Memory-Map. Reservierung von Low-Memory, Kernel-Image, Bootmodulen und Framebuffer. Unterstützt bis zu 512 MiB physikalischen Adressraum.

02

Paging & Heap

32-Bit-Paging mit Identity-Mapping und dynamisch allokierten Page Tables. Virtueller Heap bei 0x18000000 mit First-Fit-Freiliste, Split/Merge-Mechanik und Spinlock-basierter Synchronisation. Automatische Expansion über den PMM.

03

Thread-Scheduler

Präemptives Round-Robin-Scheduling via PIT IRQ0 (~10ms). TSS-basierter Ring-3-/Ring-0-Switch. Thread-Zustände: RUNNABLE, RUNNING, WAITING, ZOMBIE. Waitqueues für blockierende Synchronisation. Fork-Unterstützung.

04

VFS & Dateisysteme

Einheitliche Virtual-Filesystem-Schnittstelle mit Path-Resolver, Working-Directory und open/read/write-API. 6 Dateisysteme: RAMFS, ProcFS, DevFS, TmpFS, Initrd, Pipes. FAT32 auf generischem Blockdevice-Layer.

05

GUI & Compositor

Vollwertiges grafisches Fenstersystem mit Compositor, Window-Manager, Widgets (Button, Label, TextInput, Checkbox, Scrollbar) und Taskbar. GUI-Apps: Paint, Terminal, File Manager. Userspace-GUI via libroninui.

06

Netzwerk-Stack (lwIP)

Integrierter lwIP 2.1.3 TCP/IP-Stack mit Intel e1000 und RTL8139 Treibern. DHCP-Client, DNS-Resolver, Socket-API (Socket/Bind/Connect/Send/Recv/Listen/Accept). ICMP-Ping, UDP/TCP-Kommunikation.

07

ELF-Loader & User-Mode

32-Bit-ELF-Loader für Ring-3-Prozesse. Unterstützt ET_EXEC (fixed) und ET_DYN (PIE). Separater Adressraum pro Prozess. User-Pointer-Validierung. 55+ Syscalls via INT 0x80.

08

IPC & Signal-Handling

Shared Memory (System V, 32 Segmente, bis zu 8 MB), Semaphoren (blockierende P/V via Waitqueues), Ronin Sockets (AF_RONIN, Unix-Domain-Sockets). Unix-ähnliche Signale: KILL, TERM, INT, SEGV, PIPE, CHLD.

09

PCI & Driver Model

PCI-Bus-Enumeration (Bus 0-255, BAR-Probing). Driver Manager mit driver_register()/driver_probe_all(). Registrierte Treiber: Intel e1000, Realtek RTL8139, AHCI SATA. ATA PIO für Legacy-Geräte.

10

Dynamischer Linker

Eigener ELF32-Dynamic-Linker ld-ronin.so.1 mit PIE-Unterstützung. Shared Libraries (libc.so.1, libtest.so). Rekursives Laden von DT_NEEDED, REL/RELA-Relokationen, PLT/GOT.

11

Shell & App-System

Eigener Kommandozeilen-Parser mit Tab-Vervollständigung, Shell-History, anpassbarem Prompt ($PS1), env/set-Builtins und Pipe-Syntax (|). 30+ Shell-Apps und Builtins.

12

Framebuffer & TTY

Dynamisch berechnetes Raster aus Bildschirmauflösung und Font-Zellgröße. ANSI-Farben in VS-Code-Dark-Palette. TTY-Layer mit Raw/Cooked-Modus, Escape-Sequenz-Konvertierung und Blocking-Read via Waitqueues.

13

Input & Devices

Generisches Input-Event-System für Tastatur (PS/2, layout-konfigurierbar) und Maus (PS/2, 3 Tasten). /dev/input für Userspace. DevFS: /dev/console, /dev/serial, /dev/fb0, /dev/null.

14

Config & Boot

Persistente Key-Value-Konfiguration (/etc/roninos.conf). Boot-Commandline-Parser (nopreempt, debug, init=). BIOS/UEFI-Dual-Boot mit GRUB. Docker-Cross-Toolchain, CI via GitHub Actions.

15

Userspace-Ökosystem

Userspace-libc (printf, malloc, str*), Init-Prozess, Compositor. 20+ Programme: cat, nano, ping, gui_demo, fork_test, signal_test, mmap_test uvm.

Systemarchitektur

Vollständiger Boot- und Initialisierungsablauf – von der Systemfirmware bis zur betriebsbereiten GUI-Oberfläche. Der Kernel ist vollständig freestanding implementiert und weist keinerlei Abhängigkeiten von einer C-Standardbibliothek auf.

Dateisysteme

Sechs Dateisystemimplementierungen unter einem einheitlichen VFS-Layer mit Path-Resolver, Working-Directory, offener Dateiverwaltung und 30+ VFS-Operationen.

RAMFS Root

In-Memory-Dateisystem als Root (/). 96 Nodes, 24 Zeichen Name, 512 Bytes Content. Operationen: touch, write, append, cat, cp, mv, rm.

fs touch test.txt
fs write test.txt "Hello RoninOS"
fs cat test.txt
fs rm test.txt

FAT32 Block Device

Eigene FAT32-Implementierung auf ATA PIO / AHCI SATA. Bootsektor, FSInfo, FAT und Root-Cluster. 8.3-Dateinamen, Format/Mount/Write/Read/Delete.

fat32 format hd0 --yes
fat32 write NOTE.TXT "Hallo"
fat32 cat NOTE.TXT
fat32 rm NOTE.TXT

ProcFS Virtuell

Virtuelles Dateisystem unter /proc mit cpuinfo, meminfo, uptime und per-PID-Verzeichnissen. Ermöglicht Introspektion des Kernel-Zustands zur Laufzeit.

cat /proc/cpuinfo
cat /proc/meminfo
ls /proc/1/

DevFS Virtuell

Virtuelles /dev mit Gerätedateien für den Systemzugriff. Bereitgestellt: console, serial, fb0 (mmap-fähig), null, ram0, input.

ls /dev/
cat /dev/serial
ioctl /dev/fb0

TmpFS Temporär

Temporäres Dateisystem unter /tmp und /dev/shm. Shared Memory im Userspace. Ideal für flüchtige Daten und Interprozess-Kommunikation.

echo "test" > /tmp/data
cat /tmp/data
ls /dev/shm/

Pipes IPC

Kernel-gebufferte unidirektionale Datenströme. Blockierende Read/Write-Operationen via Waitqueues. Grundlage für Shell-Pipes (|) und Interprozess-Kommunikation.

pipe /tmp/mypipe
echo "hello" > /tmp/mypipe
cat /tmp/mypipe

Build & Run

RōninOS lässt sich via Docker (empfohlen) oder nativ mit x86_64-elf-Cross-Toolchain bauen.

1

Repository klonen

git clone https://github.com/MachuraHarry/RoninOS.git
cd RoninOS
2

BIOS-Build (ISO)

make clean && make
make verify
3

In QEMU starten

make run
make run-serial   # mit COM1-Diagnose
4

UEFI-Image + Test

make uefi-image
make uefi-run
5

Docker-Build (reproduzierbar)

scripts/build.sh
