RōninOS Vom Bootloader zur Shell – ein didaktischer Kernel in C

Ein freestanding x86-Kernel mit eigener Speicherverwaltung (PMM, Paging, Heap), präemptivem Scheduler, VFS-Layer mit RAMFS und FAT32, ELF-Loader, Framebuffer-Konsole sowie GUI-Windowing-System. Vollständig in C entwickelt, kompilierbar via Docker-Cross-Toolchain oder nativer x86_64-elf-GCC-Umgebung.

Kernkomponenten

Acht module Bereiche, die den Kernel von der Bootsequenz bis zur GUI vollständig abdecken.

01

Physical Memory Manager

Bitmap-basierte 4-KiB-Frame-Verwaltung auf Basis der Multiboot2-Memory-Map. Reserviert Niedrigspeicher, Kernel-Image, Module und Framebuffer. Obergrenze: 512 MiB physikalischer Adressraum.

02

Paging & Heap

32-Bit-Paging mit Identity-Mapping und dynamisch allokierten Page Tables. Virtueller Heap bei 0x18000000 mit First-Fit-Freiliste, Split/Merge und Spinlock-Sicherung. Selbstexpansion via PMM.

03

Thread-Scheduler

Kooperatives Round-Robin mit optionalem PIT-basiertem Preempting (100 Hz). Threads mit eigenem kmalloc-Stack, Zustandsmaschine (RUNNABLE, SLEEP, ZOMBIE) und Introspektion via ps und procmon.

04

VFS & Dateisysteme

Einheitlicher VFS-Layer mit Path-Resolver, cwd und open/read/write-API. RAMFS als Root (/), Multiboot2-Module read-only unter /initrd. FAT32-Implementierung auf generischem Blockdevice-Layer.

05

Framebuffer-Konsole

Dynamisches Raster aus Bildschirmauflösung und Font-Zellgröße. ANSI-Farben (VS-Code-Dark-Palette), 8x16-Standard-Font, optional 16x32. Debug-Overlay für FB-Parameter via DEBUG=1.

06

Shell & App-System

Eigener Kommando-Parser mit Builtins, registrierbaren Apps und VFS-Integration. App-Registry in apps.c – neue Programme durch app_<name>_main() und Tabelleneintrag.

07

GUI / Windowing

Experimentelles Fenstersystem mit Taskbar, Mauszeiger, Z-Order und macOS-artigen Traffic-Light-Buttons. Basis-Apps: Terminal, Dateimanager und Paint. VS-Code-Dark-Theme.

08

UEFI & BIOS Boot

Multiboot2-konformer Kernel-Header. BIOS-ISO, UEFI-Superfloppy-FAT32 und partitioniertes MBR/FAT32-USB-Image. GRUB mit gfxmode-Fallbackkette und videoinfo-Debug-Eintrag.

Dateisysteme

Zwei Implementierungen unter einem einheitlichen VFS-Layer mit Path-Resolver und offener Dateiverwaltung.

RAMFS In-Memory

Das Root-Dateisystem liegt vollständig im Heap. touch, write, append, cat, cp, mv, rm – alle Operationen in O(n) über eine verkettete Liste.

fs touch test.txt
fs write test.txt "Hello RoninOS"
fs cat test.txt
fs rm test.txt

FAT32 Block Device

Eigene FAT32-Implementierung auf dem generischen Blockdevice-Layer (ATA PIO). Bootsektor, FSInfo, FAT und Root-Cluster werden bei format angelegt. 8.3-Dateinamen, Einzel-Cluster-Dateien (512 B).

fat32 format hd0 --yes
fat32 write NOTE.TXT "Hallo"
fat32 cat NOTE.TXT
fat32 rm NOTE.TXT

VFS + Initrd Virtuell

Einheitliche open/read/write/readdir-Schnittstelle. RAMFS als Root (/), Multiboot2-Module read-only unter /initrd. cwd pro Shell-Prozess.

ls /
cd /initrd
cat /initrd/banner.txt

Build & Run

RōninOS lässt sich via Docker (empfohlen) oder nativ mit x86_64-elf-Cross-Toolchain bauen.

1

Repository klonen

git clone https://github.com/MachuraHarry/RoninOS.git
cd RoninOS
2

BIOS-Build (ISO)

make clean && make
make verify
3

In QEMU starten

make run
make run-serial   # mit COM1-Diagnose
4

UEFI-Image + Test

make uefi-image
make uefi-run
5

Docker-Build (reproduzierbar)

scripts/build.sh
